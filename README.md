# Employee CRAG Bot

An internal Q&A assistant that answers employee questions from company documents (PDFs), using a Corrective RAG (CRAG) pipeline: retrieve relevant chunks, grade their relevance with an LLM, and only trust the answer when the evidence actually supports it. Runs fully locally — no cloud LLM, no data leaves your machine.

## Architecture

- **LLM:** Ollama running `llama3.1:8b` locally (uses your GPU automatically, free, offline)
- **Embeddings:** `sentence-transformers` (`all-MiniLM-L6-v2`) — runs locally on CPU, no API calls
- **Vector store:** FAISS FlatL2 — local, persisted to disk
- **Web interface:** Flask, with password protection, HTTPS, and per-user question logging
- **Public access:** Cloudflare Tunnel — exposes the local server to the internet without a cloud host

## Setup

### 1. Install Ollama and pull the model
Download from [ollama.com](https://ollama.com), then:
```
ollama pull llama3.1:8b
```

### 2. Install Python dependencies
```
pip install openai pydantic numpy faiss-cpu sentence-transformers python-dotenv pypdf flask pyopenssl
```

### 3. Create your `.env` file
```
APP_PASSWORD=your_chosen_password
HR_CONTACT=hr@yourcompany.com
IT_CONTACT=it@yourcompany.com
```

### 4. Add your documents
Create a folder called `company_docs` and put your PDFs in it.

### 5. Build the index (run once, or whenever documents change)
```
python ingest_documents.py
```
This creates `faiss_index.bin` and `chunks.json`.

### 6. Run the bot

**Terminal version** (quick testing):
```
python crag_pipeline.py
```

**Web version** (real interface, what you'd actually use):
```
python app.py
```
or, for auto-restart on crash:
```
run_app.bat
```
Then open `https://localhost:5000` in a browser (you'll see a one-time self-signed certificate warning — click through it, this is expected).

## Making it accessible from anywhere (Cloudflare Tunnel)

Install `cloudflared`, then run, in a separate terminal, while the app is running:
```
cloudflared tunnel --url http://localhost:5000
```
This prints a public HTTPS URL (e.g. `https://random-words.trycloudflare.com`) that works from anywhere in the world. Note: this URL changes each time the tunnel restarts unless a permanent tunnel is set up with a custom domain.

**Important:** the host machine needs to stay on, awake, and connected to the internet for the bot to remain reachable. See the power settings section below.

## Keeping the host machine from sleeping

Windows Settings → System → Power & battery:
- "When plugged in, put my device to sleep" → **Never**
- Lid close action (while plugged in) → **Do nothing**
- Keep the machine plugged into power at all times while running as the bot's host

## How the confidence routing works

Each question is graded against the retrieved document chunks and routed based on confidence:

| Confidence | Route | Behavior |
|---|---|---|
| ≥ 0.8 | `local_only` | Answered directly from company documents, with source citations |
| 0.4 – 0.8 | `partial_escalate` | Partial answer + note pointing to HR or IT, based on question topic |
| < 0.4 | `full_escalate` | No answer generated — points directly to HR or IT |

No open web search is used — if the documents don't cover it, the bot says so honestly and points to a human contact instead of guessing.

Escalation messages automatically pick HR vs. IT based on keywords in the question (e.g. "PTO" routes to HR, "VPN" routes to IT), falling back to listing both if it's unclear.

## Logs

Every question is logged to `query_log.csv` with timestamp, username, question, confidence score, route, chunks retrieved, and answer. Open it in Excel and sort by confidence ascending to find real gaps in your documentation — questions people keep asking that the handbook doesn't clearly answer.

## Security notes

- Password-protected, HTTPS-encrypted (self-signed certificate — browsers will show a one-time warning, this is expected for local/internal use)
- No open web search — company questions never leave your infrastructure
- The shared password is not per-user authentication — the optional name field identifies "someone claiming to be X," not verified identity
- If deployed via Cloudflare Tunnel, the bot is reachable by anyone with the URL and password from anywhere in the world — treat both with the same care as any internal company credential

## Known limitations

- Runs on a personal machine, not dedicated server infrastructure — uptime depends on the host machine staying on and connected
- Single GPU means concurrent requests queue rather than process in true parallel (requests are automatically serialized to avoid GPU conflicts)
- No individual user accounts — logging identity relies on a self-reported name field, not verified authentication
- If the host machine loses power or crashes, the bot goes down until manually restarted (an auto-restart script covers software crashes, not hardware/power loss)

## Optional: Docker

`Dockerfile`, `docker-compose.yml`, and `requirements.txt` are included for running the app and Ollama as containers instead of installed directly on the host. Requires Docker Desktop with WSL2 and the NVIDIA Container Toolkit for GPU access on Windows. See inline comments in `docker-compose.yml` for details.
